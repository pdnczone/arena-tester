# VPN Arena — مقایسه ظرفیت دو پنل (3x-ui در برابر Nexora)

یک وب‌اپ که روی **سرور سوم** اجرا می‌شود، به‌صورت پله‌ای کاربر همزمان به هر دو پنل اضافه می‌کند و زنده نشان می‌دهد
هر پنل تا چند کاربر دوام می‌آورد. نمودار، شمارنده بزرگ کاربر، CPU/RAM هر سرور، و لحظه‌ی «از کار افتادن» همه روی صفحه است.

```
 [سرور ۳: VPN Arena]──درخواست HTTP / اتصال VPN──►[سرور A: 3x-ui  + agent]
   مرورگر شما ◄─ داشبورد ─┘                    └──►[سرور B: Nexora + agent]
```

## دو نوع تست

| تست | یعنی چه | «کاربر» یعنی | معیار شکست |
|---|---|---|---|
| **خود پنل (HTTP)** | سابسکریپشن کاربران (پیش‌فرض ۸۰٪) + چند درخواست ادمین با سشن مشترک | کاربر مجازی که هر ~۱ ثانیه یک درخواست می‌زند | خطا بیشتر از حد، یا p95 بیشتر از حد |
| **ترافیک VPN** | هر کاربر یک اتصال واقعی از داخل هسته Xray/sing-box است و دانلود می‌کند | اتصال همزمان با سقف سرعت مشخص (پیش‌فرض ۲Mbps) | سرعت هر کاربر زیر ۷۰٪ سقف، یا اتصال خطا بدهد |

شکست = ۳ ثانیه‌ی پیاپی خارج از حد مجاز. **ظرفیت پایدار** = آخرین پله‌ای که سالم بود.

## قوانین مقایسه‌ی عادلانه (برنامه بعضی را خودش چک می‌کند)

1. روی هر دو پنل **دقیقاً یک inbound** (پروتکل + ترنسپورت + امنیت، مثلاً VLESS+TCP+Reality) و **همان تعداد کاربر تست** (مثلاً ۵۰۰) بسازید. اگر پروتکل‌ها فرق کنند برنامه هشدار قرمز می‌دهد.
2. مشخصات و دیتاسنتر دو سرور یکی باشد؛ هر دو تازه ریستارت شده باشند.
3. برای تست VPN حالت **«پشت‌سرهم»** را بگذارید (هر دو پنل CPU و کارت شبکه‌ی سرور سوم را شریک می‌شوند). تست HTTP را می‌شود **«همزمان»** زد.
4. اگر CPU سرور سوم از ۸۵٪ بالا برود، بنر هشدار می‌آید: نتیجه محدودیت خود سرور سوم است، نه پنل.
5. کاربران تست مختلف بسازید (نه یک UUID با هزار اتصال)؛ تفاوت واقعی پنل‌ها در شمارش ترافیک و محدودیت‌های هر کاربر است.

## راه‌اندازی (یک بار)

### ۱) روی سرور A و B: ایجنت آمار
```bash
sudo TOKEN=یک_رمز_دلخواه bash agent/install.sh      # پورت پیش‌فرض 9100
sudo ufw allow from IP_سرور_سوم to any port 9100 proto tcp
```
ایجنت CPU، RAM، شبکه، تعداد TCP و **مصرف جداگانه‌ی پروسه‌ی پنل و پروسه‌ی هسته** را می‌دهد. نام پروسه‌ها را در تنظیمات بنویسید (مثلاً `x-ui` و `xray`؛ برای Nexora نام واقعی را با `ps aux` پیدا کنید).

### ۲) روی سرور سوم
```bash
cp .env.example .env   # یا فقط:  echo 'DASH_PASSWORD=رمز-قوی' > .env
docker compose up -d --build
```
بدون Docker: Node 18+ و باینری `xray` (و در صورت نیاز `sing-box`) نصب باشد، سپس
`npm install && ulimit -n 1000000 && DASH_PASSWORD=... XRAY_BIN=/usr/local/bin/xray node server.js`.

- داشبورد: `http://IP_سرور_سوم:8080` (نام کاربری هر چیزی، رمز = `DASH_PASSWORD`)
- پورت **8081** (منبع دانلود تست VPN) را **فقط برای IP سرور A و B** باز کنید، نه عمومی (وگرنه هر کسی می‌تواند ترافیک سرور سوم را مصرف کند):
  `ufw allow from IP_A to any port 8081 proto tcp` و همین برای IP_B. پورت 8080 داشبورد را هم فقط برای IP خودتان باز کنید.
- ایمیج Docker فقط Xray دارد. روی **هر دو پنل یک پروتکل Xray** (مثلاً VLESS+Reality) بسازید؛ Hysteria2/TUIC به sing-box نیاز دارد (خط کامنت‌شده‌ی Dockerfile).
- اگر GitHub روی سرور بسته است: `docker compose build --build-arg XRAY_URL=<آدرس zip هسته>`.

### ۳) تنظیمات داخل داشبورد (دکمه «تنظیمات»)
برای هر پنل: آدرس پنل (با مسیر مخفی)، یوزر/پسورد ادمین، آدرس و توکن ایجنت، لینک‌های **سابسکریپشن** کاربران تست.
در بخش سرور سوم، IP عمومی همان سرور و **سرعت کارت شبکه‌اش** (پیش‌فرض 1000Mbps) را بنویسید. بعد دکمه‌های **تست** هر پنل را بزنید:
تست درخواست‌های پنل، تست لینک‌ها، تست ایجنت، و «تست یک اتصال VPN واقعی» (سرعت و زمان اتصال را نشان می‌دهد).
رمزها و لینک‌ها بعد از ذخیره دیگر به مرورگر برنمی‌گردند.

### پنل Nexora (متن‌باز نیست)
آدرس‌ها را از خود مرورگر بردارید: DevTools ← Network ← روی درخواست راست‌کلیک ← Copy ← **Copy as cURL**، و در «+ افزودن از cURL» بچسبانید. سه چیز لازم است:
1. **ورود (login)** — نوع را «درخواست ورود» بگذارید (یوزر/پسورد خودکار با `{{username}}`/`{{password}}` جایگزین می‌شود).
2. **لیست کاربران** (سنگین‌ترین صفحه‌ی ادمین).
3. **دریافت سابسکریپشن** یک کاربر (همان لینکی که به کاربر می‌دهید → در کادر لینک‌های سابسکریپشن).

اگر پنل با توکن کار می‌کند نه کوکی، به step ورود `"extract": {"token": "data.token"}` و به بقیه `"headers": {"authorization": "Bearer {{token}}"}` بدهید.
مسیرهای پیش‌فرض 3x-ui بین نسخه‌ها فرق دارد؛ اگر «تست پنل» ✖ داد، همین روش cURL را برای 3x-ui هم انجام دهید.

## اجرای تست
نوع تست، پله‌ها (شروع، افزایش، ثانیه‌ی هر پله، سقف) و آستانه‌ها بالای صفحه است. پیشنهاد برای سرورهای بزرگ (۸+ هسته، 1Gbps):

- **HTTP**: شروع ۲۰۰، پله ۲۰۰، ۱۵ ثانیه، سقف ۱۰۰۰۰.
- **VPN دور اول — «چند کاربر همزمان؟»** (همان چیزی که می‌خواهید): سرعت هر کاربر **۱۲۸ تا ۲۵۶ kbps**، شروع ۱۰۰، پله ۱۰۰، ۲۰ ثانیه، سقف ۱۰۰۰۰ (۱۰۰۰۰ کاربر × 256kbps ≈ 2.5Gbps؛ برای 1Gbps سقف را حدود ۳۰۰۰ بگذارید). فشار روی تعداد اتصال و حسابداری هر کاربر است.
- **VPN دور دوم — «چند Mbps؟»**: سرعت هر کاربر ۰ (نامحدود) یا بالا، و ۲۰ تا ۱۰۰ کاربر. فشار روی پهنای باند است.

⚠ ترافیک تست از سرور سوم **دوبار** رد می‌شود (دانلود از سرور سوم، برگشت از تونل). اگر کارت شبکه‌ی سرور سوم هم 1Gbps باشد، قبل از اینکه پنل‌ها تمام کنند خودِ سرور سوم سقف می‌خورد و هر دو پنل در یک عدد گیر می‌کنند. برنامه این را (از روی `nicMbps`) تشخیص می‌دهد و بنر «محدودیت سرور سوم» می‌دهد؛ اگر آن بنر آمد نتیجه‌ی آن دور را برای مقایسه معتبر نگیرید. در جدول نتیجه‌ی VPN ردیف «CPU هسته به ازای هر 100Mbps» مقایسه‌ی منصفانه‌ی بازدهی دو پنل است.

در پایان: بنر برنده، جدول مقایسه، و دانلود CSV/JSON.

**داشبورد** (طراحی بر پایه‌ی رهنمودهای Apple HIG؛ حالت روشن و تاریک خودکار از سیستم، فونت سیستمی): بالا نوار ابزار، بعد «مسابقه‌ی ظرفیت» (هر پنل یک نوار؛ ✕ = نقطه‌ی شکست، فلش = ظرفیت پایدار، تاج = برنده)، بعد برای هر پنل یک کارت: وضعیت (پایدار / افت کیفیت / از کار افتاد، با آیکون جدا از رنگ)، تعداد کاربر، میدان نقطه‌ای کاربران (قرمز = بالاتر از ظرفیت پایدار)، گیج‌های CPU / RAM / تأخیر / خطا / توان عملیاتی / سرعت هر کاربر، نوار تفکیک مصرف پروسه‌ی پنل و هسته، و نمودار فشار نسبت به حد مجاز. زیر آن نوار پیک‌ها و منحنی‌های مقایسه‌ی دو پنل. رنگ‌ها: سبز/نارنجی/قرمز فقط وضعیت‌اند، آبی و بنفش فقط هویت دو پنل. دکمه‌ی «تنظیم تست» پله‌ها و آستانه‌ها را با اسلایدر تنظیم می‌کند و «ضبط» IP و اطلاعات حساس را برای ویدیو تار می‌کند.

## تمرین بدون سرور واقعی
```bash
npm install
node tools/mock.js &                                   # دو پنل ساختگی با ظرفیت ۴۰۰ و ۷۰۰ req/s
XRAY_BIN=$PWD/tools/fake-xray.sh node server.js        # هسته‌ی ساختگی برای تمرین تست VPN
```
هسته‌ی ساختگی حدود 100Mbps بیشتر عبور نمی‌دهد؛ برای تمرین VPN سرعت هر کاربر را حدود 500kbps بگذارید. در تنظیمات آدرس پنل‌ها را `http://127.0.0.1:9201` و `9202` (برای ایجنت هم همان) بگذارید، نام‌کاربری/رمز هر چیزی، و لینک سابسکریپشن `http://127.0.0.1:9201/sub/1`.

## هشدارها
- فقط سرورهای خودتان را تست کنید؛ این حجم ترافیک ممکن است در دیتاسنتر شبیه حمله دیده شود. قبلش با سرویس‌دهنده هماهنگ کنید و اگر ترافیک حجمی است هزینه‌اش را در نظر بگیرید.
- پورت ایجنت (9100) و داشبورد را عمومی باز نگذارید.
- ساخته‌شده و با پنل‌های ساختگی و هسته‌ی ساختگی آزمایش شده؛ **با 3x-ui و Nexora واقعی و Xray واقعی هنوز اجرا نشده**. قبل از ضبط ویدیو یک دور کوتاه آزمایشی بزنید.
