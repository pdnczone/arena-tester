# arena-tester

یک تستر ظرفیت با داشبورد گرافیکی: با آن می‌توانید ببینید یک سرور یا یک پنل تا چند کاربر همزمان، چند درخواست در ثانیه و چند مگابیت ترافیک را تحمل می‌کند، و دو سرور (یا دو پنل) را کنار هم مقایسه کنید. کاربران را پله‌پله زیاد می‌کند و زنده نشان می‌دهد هر سرور در چه نقطه‌ای از کار می‌افتد.

## نصب (یک دستور روی سرور تستر)

روی یک سرور جدا (Ubuntu/Debian) که سرورهای تحت تست نیست، این را Paste کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/pdnczone/arena-tester/main/install.sh | sudo bash
```

همه‌چیز را خودش نصب می‌کند (Docker، برنامه، رمز تصادفی) و در پایان **لینک داشبورد و رمز** را چاپ می‌کند. وارد لینک شوید و رمز را بزنید (نام کاربری هر چیزی). به‌روزرسانی: همین دستور را دوباره بزنید.

## استفاده

۱. داشبورد ← دکمه‌ی **سرورها**.
۲. برای هر سرور: نوع پنل، آدرس پنل، نام کاربری و رمز ادمین را بدهید ← **اتصال و بررسی**.
۳. **ساخت خودکار کاربران تست**: برنامه از طریق API خود پنل inbound و کاربران تست را می‌سازد (و بعداً با «حذف کاربران تست» پاک می‌کند). روی سرور پنل لازم نیست کاری انجام دهید.
۴. (اختیاری، پیشنهادی) **ایجنت**: همان‌جا یک دستور آماده نشان می‌دهد؛ آن را یک بار روی سرور پنل Paste کنید. ایجنت خودش نصب می‌شود و خودش به داشبورد وصل می‌شود. اگر نصبش نکنید، آمار CPU و RAM از خود API پنل گرفته می‌شود که کم‌دقت‌تر است و مصرف پروسه‌ی پنل و هسته را جدا نشان نمی‌دهد.
۵. **شروع تست**.

### پنل‌های پشتیبانی‌شده
| پنل | اتصال و ساخت کاربر تست |
|---|---|
| 3x-ui | خودکار (API پنل) |
| Nexora | خودکار (API رسمی Nexora با OpenAPI)؛ فقط یک inbound باید از قبل در پنل ساخته شده باشد |
| هر پنل یا سرور دیگر | دستی: آدرس‌ها را با «Copy as cURL» مرورگر وارد کنید، یا لینک سابسکریپشن / کانفیگ کاربران را بچسبانید |

درایور پنل جدید = یک فایل کوچک در `lib/drivers/` (login، status، provision، deprovision).

## دو نوع تست

| تست | یعنی چه | «کاربر» یعنی | معیار شکست |
|---|---|---|---|
| **خود پنل (HTTP)** | سابسکریپشن کاربران + چند درخواست ادمین | کاربر مجازی که هر ~۱ ثانیه یک درخواست می‌زند | خطا بیشتر از حد، یا p95 بیشتر از حد |
| **ترافیک VPN** | هر کاربر یک اتصال واقعی از داخل Xray/sing-box است و دانلود می‌کند | اتصال همزمان با سقف سرعت مشخص | سرعت هر کاربر زیر ۷۰٪ سقف، یا خطای اتصال |

شکست = ۳ ثانیه‌ی پیاپی خارج از حد مجاز. **ظرفیت پایدار** = آخرین پله‌ای که سالم بود.

## نکات مقایسه‌ی عادلانه
- روی هر دو سرور **همان پروتکل و ترنسپورت** را بسازید (برنامه هشدار می‌دهد اگر فرق کند)، با مشخصات و دیتاسنتر یکسان.
- تست VPN را «پشت‌سرهم» بزنید؛ هر دو سرور CPU و کارت شبکه‌ی سرور تستر را شریک می‌شوند. اگر CPU یا کارت شبکه‌ی سرور تستر از ۸۵٪ بگذرد، بنر هشدار می‌آید و آن دور برای مقایسه معتبر نیست.
- برای «چند کاربر همزمان؟» سرعت هر کاربر را ۱۲۸ تا ۲۵۶ kbps بگذارید؛ برای «چند Mbps؟» سرعت را بالا یا نامحدود بگذارید و ۲۰ تا ۱۰۰ کاربر.
- ترافیک تست از سرور تستر دوبار رد می‌شود (دانلود از آن، برگشت از تونل). سرعت کارت شبکه‌اش را در تنظیمات بنویسید.

## فایروال
- روی سرور تستر: پورت ۸۰۸۰ (داشبورد) و ۸۰۸۱ (منبع دانلود تست VPN). ۸۰۸۱ را فقط برای IP سرورهای تحت تست باز کنید. ایجنت‌ها برای ثبت‌نام به ۸۰۸۰ وصل می‌شوند؛ اگر ufw فعال است: `ufw allow from IP_سرور_پنل to any port 8080 proto tcp`.
- روی سرورهای تحت تست: نصب ایجنت اگر ufw فعال باشد، پورت ایجنت (۹۱۰۰) و پورت inbound تست (۲۴۴۴۳) را فقط برای IP سرور تستر باز می‌کند.

## داشبورد
طراحی بر پایه‌ی رهنمودهای Apple HIG: حالت روشن و تاریک خودکار، فونت سیستمی، مسابقه‌ی ظرفیت (هر سرور یک نوار؛ ✕ = نقطه‌ی شکست، فلش = ظرفیت پایدار، تاج = برنده)، برای هر سرور وضعیت (پایدار / افت کیفیت / از کار افتاد)، تعداد کاربر، میدان نقطه‌ای کاربران، گیج‌های CPU / RAM / تأخیر / خطا / توان عملیاتی / سرعت هر کاربر، تفکیک مصرف پنل و هسته، و نمودارهای مقایسه. رنگ‌ها: سبز/نارنجی/قرمز فقط وضعیت‌اند و آبی/بنفش فقط هویت دو سرور. دکمه‌ی «ضبط» IP و اطلاعات حساس را برای ویدیو تار می‌کند.

## بدون Docker
Node 18+ و باینری `xray` (برای تست VPN؛ برای hysteria2/tuic هم `sing-box`) نصب باشد:
`npm install && ulimit -n 1000000 && DASH_PASSWORD=... XRAY_BIN=/usr/local/bin/xray node server.js`

## تمرین بدون سرور واقعی
```bash
npm install
node tools/mock.js &                                   # دو پنل ساختگی (شکل API های 3x-ui و Nexora) با ظرفیت ۴۰۰ و ۷۰۰ req/s
XRAY_BIN=$PWD/tools/fake-xray.sh node server.js        # هسته‌ی ساختگی برای تمرین تست VPN
```
در تنظیمات آدرس پنل‌ها را `http://127.0.0.1:9201` (نوع 3x-ui) و `http://127.0.0.1:9202` (نوع Nexora) بگذارید، نام کاربری/رمز هر چیزی.

## هشدارها
- فقط سرورهای خودتان را تست کنید؛ این حجم ترافیک ممکن است شبیه حمله دیده شود. قبلش با سرویس‌دهنده هماهنگ کنید و اگر ترافیک حجمی است هزینه‌اش را در نظر بگیرید.
- درایورهای 3x-ui و Nexora از روی مستندات (و با پنل‌های ساختگی) نوشته و آزمایش شده‌اند، **نه روی پنل واقعی**. اگر نسخه‌ی پنل شما فرق داشته باشد، دکمه‌ی «اتصال و بررسی» همان‌جا دلیل را نشان می‌دهد؛ لطفاً در Issues گزارش دهید.
- رمزها و توکن‌ها فقط روی سرور تستر (`data/config.json`) ذخیره می‌شوند و به مرورگر برنمی‌گردند.
